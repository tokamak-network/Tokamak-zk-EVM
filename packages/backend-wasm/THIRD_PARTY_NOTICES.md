# Third-Party Notices

This document is for application developers and distributors who consume
`@tokamak-zk-evm/snark-browser-compat`. It distinguishes code embedded in this package
from dependencies that remain external npm packages.

code is not copied into the backend-wasm npm tarball, but a consuming
application's bundler may include it in the application's distribution.

`wasmbuilder`, `wasmcurves`, and `web-worker` are transitive dependencies of
`ffjavascript`. The installed npm packages carry their own license files.

This package's `MIT OR Apache-2.0` license does not override these dependency
licenses. In particular, an application distribution that imports, links, or
bundles backend-wasm with `ffjavascript` must comply with the applicable GPL
obligations for the resulting combination. Externalizing `ffjavascript` from
the converter Worker prevents duplicate package code; it does not remove those
obligations.

## Generated Tokamak material

The published prover includes setup parameters, packed R1CS data, and subcircuit
metadata generated from `@tokamak-zk-evm/subcircuit-library@2.1.3`. The
published verifier includes CRS data generated from the Tokamak zk-EVM native
backend setup output for version 2.1.3. These sources follow the Tokamak zk-EVM
repository's `MIT OR Apache-2.0` policy. The complete license texts are in
`LICENSE-MIT` and `LICENSE-APACHE`.

## Embedded RKYV decoder

The converter Worker contains JavaScript glue generated by
`wasm-bindgen-cli@0.2.126` and
`backend_wasm_rkyv_decoder_bg.wasm`. The WASM binary statically contains
backend-wasm's decoder and its normal Rust dependency graph. For components
offered under `MIT OR Apache-2.0`, this distribution selects the MIT option.
Exact selected upstream license files are preserved under
`third-party-licenses/rkyv-decoder-wasm`. Build-only tools, derive macros, and
proc-macro dependencies are not included in that directory because their code
is not linked into the distributed WASM object.
